# История изменений

Заметные изменения проекта перечисляются в этом файле. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют
[Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

## [0.7.0] - 2026-07-16

### Добавлено

- Единый точечный API `byIds()`, `find()` и `require()` для категорий, счетов,
  источников, тегов и валют.
- Типизированный CRUD финансовых справочников: категории, обычные счета,
  источники, теги и стандартные валюты.
- `ReferenceWriteToken` для контролируемого немедленного повтора создания
  справочного объекта с тем же `client_id`.
- Дерево и `<select>`-опции тегов, а также поля `description` у категорий и
  источников и `userId` у тегов.
- Живой CRUD-набор справочников с двухпроходной уборкой, восстановлением
  default-валюты и проверкой отсутствия оставшихся fixtures.

### Изменено

- `categories()->update()` и `places()->update()` теперь возвращают
  типизированный перечитанный DTO вместо сырого массива ответа.
- Все справочные update-методы выполняют read-modify-write с проверкой полного
  доступа; обычный пользовательский patch принимает для boolean-полей только
  настоящий PHP `bool`, а полный legacy payload Category/Place остаётся
  совместим с точными SOAP-токенами.
- Все типизированные справочные `delete()` требуют полного доступа, сначала
  проверяют принадлежность ID конкретному типу и возвращают `false` для
  отсутствующего объекта без опасного общего удаления.
- Перед типизированной мутацией валют старый `CurrencyCatalog` инвалидируется,
  поэтому потерянный или некорректный write-ответ не оставляет доступным
  потенциально устаревший кэш.

### Безопасность данных

- SDK отклоняет update/default для crypto/investing валют: legacy
  `setCurrencyList` принудительно сбрасывает `ratio` и `is_investing`.
- Нельзя удалить default-валюту, пока другая валюта не назначена default.
- `createAccount()` создаёт только обычный счёт и не обещает небезопасное
  создание папок, кредитных карт или системных долговых объектов.
- Удаление родительской категории сохраняет legacy cascade-семантику; источники
  используют тот же иерархический object-delete, поэтому leaf-only поведение не
  обещается.
- `places()->delete()` работает только для обычного пустого счёта и проверяет
  весь журнал, включая плановые операции; server-side race legacy API явно
  задокументирован.
- `tags()->update()` и `tags()->delete()` отклоняют теги другого участника семьи
  или строки без `user_id`, чтобы update не переписал владельца, а delete не
  удалил чужой видимый семейный тег.

## [0.6.0] - 2026-07-16

### Добавлено

- `RecordPatch` для частичного обновления операций без ручной реконструкции
  большого `Record`.
- Типизированный `WriteResult` с server/client ID, исходным SOAP-ответом и
  совместимыми `foreach`, `count()` и array-access операциями чтения.
- `RecordWriteToken` для контролируемого немедленного повтора записи с теми же
  `client_id`, а для группы расходов — и `group_id`.
- Структурированные `SoapFaultException` и `AmbiguousMutationException`;
  транспортные исключения теперь содержат `method`, `endpoint`, `retrySafe` и
  `faultCode`.
- Типизированные transport options: connect/read timeout и `WsdlCache`.

### Изменено

- `records()->create*()` и `records()->update()` теперь возвращают
  `WriteResult`. Низкоуровневый `savePayloads()` по-прежнему возвращает сырой
  список.
- `records()->update()` явно отклоняет перемещения и обмены: legacy API требует
  обе связанные строки, а одиночный `Record` не содержит безопасного полного
  patch-контракта для пары.
- По умолчанию SOAP использует connect timeout 10 секунд, read timeout 30
  секунд и WSDL memory cache. Raw `soapOptions` остаются escape hatch и имеют
  приоритет над типизированными настройками.
- Failover и одиночный endpoint одинаково различают безопасный повтор до
  отправки и неоднозначный результат уже отправленной записи.

### Исправлено

- `MoneyAmount` больше не переполняет integer незаметно при больших значениях и
  корректно форматирует `PHP_INT_MIN`.
- `absolute()` и `negate()` явно отклоняют единственное непредставимое
  положительное значение, а `fromFloat()` проверяет finite/range.

### Устарело

- `MoneyAmount::fromFloat()` из-за недетерминированной двоичной точности.
- `MoneyAmount::withScale()`, который меняет смысл minor units. Для сохранения
  суммы используй `rescale()`, для явной переинтерпретации —
  `reinterpretScale()`.

## [0.5.1] - 2026-07-15

### Добавлено

- Раздельные команды и флаги для read-only и записывающих live-тестов;
  write-suite удаляет свои fixtures до и после каждого сценария и подтверждает
  отсутствие остатков повторным чтением API.
- CI для поддерживаемых версий PHP, минимальных зависимостей и PHPStan на
  максимальном уровне без baseline.

### Исправлено

- Даты из SOAP теперь принимаются только в точном формате Дребеденег и не
  нормализуются PHP незаметно для вызывающего кода.
- Скалярные ответы аккаунта и синхронизации, включая boolean tokens и статусы
  удаления, проверяются до преобразования типов.
- Частичное обновление категорий и мест хранения теперь сначала читает объект,
  проверяет полный доступ, собирает полный SOAP payload и меняет только явно
  разрешённые поля. Полные legacy payload остаются совместимыми, а HTML-текст не
  экранируется повторно. Папки, credit-card и системные долговые счета, которые
  legacy API не умеет обновить без потери состояния, отклоняются до записи.
- Некорректные необязательные скаляры, поля SOAP-списков и ответы удаления больше
  не приводятся незаметно к пустым значениям.
- Неудачное обновление каталога валют, включая ответ с повторяющимся ID, больше
  не оставляет частично заполненный или противоречивый кэш.
- Read-only failover снова проверяет остальные endpoint, включая ранее
  недоступный primary. `getRecordList` повторяется только при явном
  `is_report=true`, поэтому state-changing `initialRecords()` никогда не уходит
  автоматически на второй endpoint. После отказа всех endpoint sticky-выбор
  очищается, и следующая запись сначала выполняет безопасный probe.
- Legacy SOAP options из третьего аргумента `fromCredentials()` объединяются с
  четвёртым аргументом, причём явно переданный четвёртый аргумент имеет приоритет.

## [0.5.0] - 2026-07-14

### Добавлено

- Типизированные запросы истории операций, баланса и финансовых отчётов.
- Валютно-зависимая точность денежных сумм и точный `DecimalMoneyAmount` для
  агрегированных отчётов.
- Безопасный явный failover и классификация транспортных ошибок.

### Изменено

- Чтение истории отделено от state-changing первоначальной синхронизации.
- Ответы финансовых и справочных методов валидируются на границе SOAP.
