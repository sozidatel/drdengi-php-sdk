# Подготовленные операции

`RecordService::prepare*()` фиксирует окончательные данные новой операции до
отправки. Полученный `PreparedRecordWrite` можно показать, сохранить в журнал
или передать другому процессу. `RecordService::submit()` отправляет эти же
данные и возвращает `WriteResult`.

Автономный пример: `php examples/prepared_record.php`. Он использует фиктивный
транспорт и подготовленный справочник, показывает JSON и имитирует отправку
восстановленной операции без сети и credentials.

## Подготовка

Доступны `prepareExpense()`, `prepareIncome()`, `prepareTransfer()`,
`prepareExchange()` и `prepareExpenseGroup()`. Их аргументы, включая необязательный
`RecordWriteToken`, совпадают с соответствующими `create*()`.

Подготовка выполняет существующие проверки суммы и валюты. Если справочник
валют ещё не загружен, возможно его чтение с сервера. `setRecordList` на этом
этапе не вызывается. Дата сразу переводится в timezone из `ClientOptions`,
суммы — в целые минимальные единицы валюты, идентификаторы и связи строк
создаются один раз.

Объект содержит:

- `payloads` — окончательные строки SOAP-запроса, включая client IDs и связи;
- `amounts` — точные `MoneyAmount` с зафиксированной валютной точностью, в том
  же порядке, что и строки; сумма сохраняет знак расхода или прихода;
- `count($prepared)` — количество отправляемых строк. Перевод и обмен содержат
  по две строки, группа расходов — по одной на позицию.

Данные неизменяемы. Изменение исходного `DateTime` или массива после подготовки
не меняет объект. Если нужно изменить операцию после просмотра, подготовь
новый объект и проверь его содержимое.

Пустая группа создаёт пустой объект без чтения валют и проверки размера токена.
Её отправка возвращает `WriteResult::empty()` без сетевого запроса. Группа из
одной позиции сохраняет обычную форму расхода без `group_id`.

## Сохранение и восстановление

`toJson()` и `json_encode($prepared, JSON_THROW_ON_ERROR)` сохраняют объект.
Для восстановления доступны `PreparedRecordWrite::fromJson($json)` и
`PreparedRecordWrite::fromArray($data)`.

Формат содержит `version: 1`, список `payloads` и список `scales` с точностью
каждой соответствующей суммы. Суммы сохраняются целыми числами, а даты — уже
отформатированными строками. Не преобразовывай суммы через float; при обработке
JSON в JavaScript большие целые PHP могут потерять точность. Для хранения и
передачи сохраняй исходный JSON без такого преобразования.

Неизвестная версия, некорректный JSON, неверные типы или повреждённая структура
вызывают `InvalidArgumentException`. Восстановление не обращается к серверу и
не генерирует новые идентификаторы. Оно проверяет структуру данных, но не
подлинность файла: приложение отвечает за сохранность и доступ к нему.
Получай снимки через `prepare*()`: восстановление не повторяет все проверки
финансового смысла вручную собранных строк и не заменяет подготовку операции.

В объекте нет пароля, API credentials, адреса сервера или привязки к аккаунту.
Сохраняй идентификатор целевого аккаунта отдельно и выбирай соответствующий
клиент при отправке. Сам JSON содержит финансовые данные, включая комментарии.

## Отправка и неизвестный результат

`submit($prepared)` передаёт сохранённые `payloads` существующему пути записи.
Справочник валют при этом не перечитывается, сумма и дата не пересчитываются.
Изменившаяся timezone клиента не меняет запрос. Если за время хранения
изменились валюта, её точность или целевой аккаунт, нужна новая подготовка и
проверка операции.

Ответ проверяется по прежним правилам. Полное подтверждение возвращает
`WriteResult`; неполное или некорректное — `UnconfirmedWriteException` с
исходными строками и ответом. Сетевой сбой после отправки может дать
`AmbiguousMutationException`. Объект остаётся доступен вызывающему коду для
сверки, но состояние отправки внутри него не хранится.

Приложение само сохраняет журнал попыток и их результат. Повторный вызов
`submit()` действительно снова отправит запрос. SDK не ставит отметку
«отправлено» и не выполняет автоматических повторов.

Подготовленный объект не расширяет гарантии legacy API:

- Следующий успешный `setRecordList` для того же API ID заменяет прежние
  соответствия дедупликации; первоначальная синхронизация также сбрасывает их.
- Для допустимого немедленного повтора после неоднозначного результата нужны
  те же данные и тот же endpoint. При неизвестном endpoint или промежуточных
  записях сначала сверь журнал чтением.
- Парные операции и группы не получают гарантии серверной транзакции или
  автоматического отката.

## Совместимость

Существующие `create*()` выполняют подготовку и немедленную отправку. Их
именованные аргументы и значения по умолчанию, сформированные SOAP-строки,
результаты и обработка ошибок сохраняются. Для обычного создания одной
операции по-прежнему достаточно одного вызова.

Подготовка относится к созданию расходов, доходов, переводов, обменов и групп
расходов. `update()`, `delete()` и низкоуровневый `savePayloads()` продолжают
работать по существующим правилам.
