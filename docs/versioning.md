# Версии и совместимость

Проект следует Semantic Versioning с учётом того, что до 1.0 публичный API ещё
может уточняться.

- Patch-релиз исправляет ошибки и может начать отклонять данные, которые уже не
  соответствуют документированному контракту.
- Minor-релиз добавляет возможности и до 1.0 может содержать ограниченные
  несовместимые изменения. Они обязательно описываются в `UPGRADING.md`.
- После 1.0 несовместимое изменение публичного API требует major-релиза.

Публичным API считаются классы, методы, аргументы, возвращаемые DTO и исключения
в namespace `Soz\Drebedengi`. Содержимое `raw`, точный порядок внутренних SOAP
вызовов и классы из `tests` контрактом стабильности не являются.

Минимальная версия PHP задаётся в `composer.json`; конкретные поддерживаемые
ветки перечислены в матрице CI. Новая будущая версия PHP может работать по
ограничению Composer, но считается проверенной только после добавления в эту
матрицу. Перед повышением минимальной версии PHP или удалением deprecated API
публикуется инструкция обновления.
